# Краткий отчёт по алгоритмам SimHash и MinHash

## 1. Выбор алгоритмов

Для работы были выбраны вероятностные алгоритмы **SimHash** и **MinHash**. Оба алгоритма применяются для поиска похожих текстов, но используют разные подходы.

SimHash преобразует документ в компактный 64-битный отпечаток. Сходство документов определяется с помощью расстояния Хэмминга между отпечатками. Алгоритм был выбран благодаря небольшому размеру результата и высокой скорости сравнения.

MinHash оценивает сходство множеств шинглов и приближает коэффициент Жаккара. Он был выбран в качестве второго алгоритма, поскольку позволяет решить ту же задачу другим вероятностным методом и сравнить скорость, точность и требования к памяти.

В стандартной библиотеке Java готовые реализации SimHash и MinHash отсутствуют, поэтому оба алгоритма были реализованы самостоятельно.

## 2. Архитектура проекта

Проект разделён на несколько логических уровней.

Пакет `libs` содержит собственные реализации SimHash и MinHash, хеш-функции, извлечение шинглов и вычисление сходства.

Пакет `service` предоставляет интерфейс для использования алгоритмов и выполняет проверку входных параметров.

Пакет `dataset` отвечает за чтение размеченных пар документов из CSV-файлов. Большие файлы обрабатываются потоково, поэтому весь набор данных не загружается в оперативную память.

Пакет `experiment` содержит подбор параметров и вычисление метрик качества: accuracy, precision, recall, F1, FPR и FNR. Для MinHash дополнительно вычисляется ошибка относительно точного коэффициента Жаккара.

Пакеты `benchmark` и `demo` используются для запуска экспериментов, измерения времени работы и вывода результатов.

Такое разделение позволяет независимо изменять реализацию алгоритма, источник данных и способ проведения эксперимента.

## 3. Наборы данных

Для демонстрации и подбора параметров использовались небольшие размеченные наборы `train`, `validation` и `test`, размещённые в ресурсах проекта.

На обучающем и проверочном наборах выбирались размер шингла, порог сходства и размер MinHash-подписи. После выбора параметры фиксировались и проверялись на тестовом наборе.

Для нагрузочного тестирования был использован немецкоязычный корпус FineWiki. На его основе были подготовлены CSV-файлы, содержащие 10 000, 50 000 и 100 000 пар документов.

Положительные примеры представляли собой исходный текст и его изменённую версию. Отрицательные примеры состояли из разных документов. Размер самого большого файла составил около 487 МБ.

Большие наборы хранились вне ресурсов приложения и передавались программе как обычные файлы. Это позволило проверить работу алгоритмов на значительном объёме данных без увеличения размера собранного приложения.

## 4. Сравнение SimHash и MinHash

Оба алгоритма показали практически линейный рост времени выполнения при увеличении количества пар документов.

SimHash оказался быстрее. На наборе из 100 000 пар его пропускная способность составила около 1937 пар в секунду. Это объясняется тем, что результатом является один 64-битный отпечаток, а сравнение выполняется одной операцией вычисления расстояния Хэмминга.

MinHash обработал около 1762 пар в секунду. Он работает немного медленнее, поскольку формирует множество шинглов и подпись из 64 хеш-значений. Кроме того, в эксперименте для MinHash вычислялся точный коэффициент Жаккара, необходимый для оценки ошибки приближения.

При этом MinHash показал более высокую точность. На наборе из 100 000 пар accuracy составила около 99,49% против 98,79% у SimHash. Особенно заметно уменьшилось количество ложноположительных результатов.

Таким образом, SimHash лучше подходит для случаев, когда важны скорость, компактность и низкое потребление памяти. MinHash требует больше ресурсов, но обеспечивает более точную оценку сходства множеств признаков.

Сравнение со стандартной реализацией Java не проводилось, поскольку JDK не содержит таких алгоритмов. Корректность MinHash дополнительно проверялась сравнением его результата с точным коэффициентом Жаккара, а обе реализации тестировались на одинаковых размеченных наборах данных.

## Подготовка больших наборов данных

Для создания больших тестовых наборов использовался Python-скрипт:

```text
tools/hw22/prepare_finewiki_simhash.py
```

Скрипт загружает немецкие статьи корпуса FineWiki в потоковом режиме и формирует размеченные пары документов:

* положительная пара — исходный текст и его автоматически изменённая версия;
* отрицательная пара — два разных документа.

Для запуска требуется Python 3 и библиотека `datasets`.

Создание виртуального окружения:

```powershell
py -m venv .venv-data
```

Установка зависимости:

```powershell
& .\.venv-data\Scripts\python.exe -m pip install datasets
```

Создание набора из 10 000 пар:

```powershell
& .\.venv-data\Scripts\python.exe tools\hw22\prepare_finewiki_simhash.py `
    --output datasets\hw22\finewiki_de_pairs_10000.csv `
    --pairs 10000
```

Аналогично создаются более крупные наборы:

```powershell
& .\.venv-data\Scripts\python.exe tools\hw22\prepare_finewiki_simhash.py `
    --output datasets\hw22\finewiki_de_pairs_50000.csv `
    --pairs 50000
```

```powershell
& .\.venv-data\Scripts\python.exe tools\hw22\prepare_finewiki_simhash.py `
    --output datasets\hw22\finewiki_de_pairs_100000.csv `
    --pairs 100000
```

Полученные CSV-файлы сохраняются в каталоге:

```text
datasets/hw22/
```

Один и тот же набор данных используется для тестирования SimHash и MinHash, что обеспечивает сопоставимость результатов двух алгоритмов.

Скрипт подготовки данных приложен к проекту. Большие CSV-файлы могут быть созданы повторно указанными командами и поэтому не включаются в исходный код проекта.
